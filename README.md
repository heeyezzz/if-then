# 布谷（If-Then）

> 应用名「布谷」——布谷鸟到点就鸣：提前订好的「如果……就……」预案，在当下真的发生、按时提醒你。

一个个人用的 if-then 决策预案安卓 app，实践心理学中的 **implementation intentions**（执行意图）：提前写好「如果遇到 X，就执行 Y」，在诱惑/状态出现的当下不靠临场意志力，直接照案执行。

不是 Tasker 那类手机自动化，也不是 AI 工作流引擎——它管理的是**你和自己订的行为预案**。

## 核心循环

```
写预案 → 触发时一步打卡 → 晚上补记 → 复盘统计 → 修订预案库
```

- **两类预案**：**长期**（反复照案执行的习惯清单）与**一次性**（情境只来一次，做完或没做都当场结清、然后从清单消失）。底部四个板块 `一次性 · 长期 · 复盘 · 设置`，在页面空白处左右滑即可切页——卡片上起手仍是打卡/露按钮，不会误翻页
- **手动打卡**：点「今天的现场」药丸一下即完成；卡片右滑也=完成（有音效和回弹动画）
- **卡片手势**：右滑完成 · 左滑露出圆钮 · 点卡片进编辑 · 展开后点空白或滚动列表自动归位。长期卡是「没做 / 移夹 / 归档 / 删除」，一次性卡是「没做 / 改长期 / 归档 / 删除」
- **语义标签**：每张卡用「如果」（松绿实心）与「就」（琥珀）两个小标签显式标注条件与动作，共用一列让正文左边缘对齐
- **今日状态一眼可辨**：长期卡片按**今天最新一条记录**判四态——今天做了＝整卡变淡＋「就」行划删除线＋右下角戳记 `今天 08:32 ✓`（最小版标「最小版」，补记标「补记」不写时刻）；今天记了没做＝**不变淡**、只加琥珀小标 `今天 08:32 · 没做`；补记待确认＝灰标 `今天 · 待确认`；今天没动＝原样。同一天后一次打卡覆盖前一次（先做后改没做就显示没做，反之亦然），链条的「今天 x/y」同口径。顶部药丸、链条节点、复盘战绩列表都跟着同步，打卡后 180ms 淡变过渡
- **一次性预案**：可选填「哪天之前」，逾期只标红字提醒并沉底——**系统绝不自动改状态**，结清只能出自你的打卡；当天已结清的灰显在「今天已结清」里，点进去可「重新挂起」（打卡记录保留）
- **任务连锁**：链是独立实体——有自己的名字、颜色、所属文件夹，能整条归档/删除。两种建法：新建时选「建一串预案」一次写好几步自动接成链；或在编辑页给长期预案指定「下一步接哪个」。首页链默认折叠成一行摘要（色点+名字+`N 步 · 今日 x/N`），点箭头才展开成员卡，打卡只在展开的卡上做；链头的 ⋯ 菜单管整条（编辑整串/归档/设色/删除整串）。做完上一步后页首浮现「▶ 下一步 · 接「X」之后」提示条（点=打卡，跳过=标没做并推进），整条做完换成 🎉 并响一段上行三音。中途「没做」只跳过、不断链；摘出或删掉中间节点会自动把前后接上，链掉到只剩 1 步自动散成普通预案
- **排序模式**：标题栏 ⇅ 进入，每张卡（含文件夹行与一次性清单）右侧出现 ①序号 + ▲▼⇈⇊，点一下移一格、长按箭头连续移动；链条成员跟着头部整体移动。每次点击即时落库，返回键先退出排序模式
- **文件夹**：服务长期预案和链。点右侧箭头可在当前页行内展开该夹的内容（不跳页）；点整行才进入文件夹；长按改名/改外观/连带删除。一条链整条归一个夹，链摘要行和散预案在夹内同级混排
- **两分钟版**：每条预案可选配一个"必然能完成"的退化版（跑步→穿上跑鞋出门站一分钟）。卡片第三行灰字显示，**点它就算「做了」**——连击不断、热力图照常亮、链条照常推进；先固化"做"这个动作本身，再谈剂量。复盘里单独看"30 天里有多少次只做了两分钟版"，当状态预警用，不当羞耻记录。注意：它必须挂在某条 if-then 上，不是独立的待办清单
- **补记三态**：每条记录是 `做了 / 没做 / 待定`，复盘页可「补记触发」生成待定项，睡前翻流水补齐（补记只更新数据，不放音效和庆祝；候选清单只列长期预案）。补记的记录带 `backfill` 标记，卡片上会注明「补记」而不是写一个对不上的时刻
- **复盘闭环**：整页统计口径可按 7天/30天/全部 切换，从报数改成给结论。连击（连续顶住次数）、执行率（样本不足不给百分比）、30 天热力图（一次性也算一次行动）、最常触发（真实战场）、僵尸预案（两周没触发，建议归档）、链条健康（窗口内走通几天、最常断在第几步，活跃天数不足不下结论）、一次性战绩（完成/落空/待办/逾期 + 完成率）
- **AI 帮写**：描述困扰 → 模型出 3~5 条候选预案 → 人工勾选确认才入库（AI 不直接污染预案库）；在哪个页生成就建成哪一类

## 界面

| 页面 | 内容 |
|---|---|
| 一次性 | 待结清清单（逾期沉底并标红）+ 今天已结清；扁平一页，不分文件夹、不进链条 |
| 长期 | 「下一步」提示条 + 「今天的现场」高频药丸（按触发统计自动选前 6 条，点一下即打卡）+ 文件夹细行 + 当前层的预案卡片与链摘要行（链默认折叠，点箭头展开成员卡）+ 排序模式 |
| 复盘 | 口径切换（7天/30天/全部）、今日流水、热力图（含"多少次只做了两分钟版"）、按文件夹分节的战绩汇总（每条带今日状态点：实心绿=做了、实心琥珀=没做、空心=待确认）、僵尸预案、最常触发、链条健康、一次性战绩、已归档 |
| 新建/编辑 | 长期/一次性开关、如果…那就…、两分钟版（可选）、所在文件夹（仅长期）、哪天之前（仅一次性，可选）、下一步接哪个预案（仅长期，建链/换接/取消）、重新挂起、归档/删除、AI 生成候选 |
| 整串编辑 | 链名（留空自动取第一步「如果」）、所在文件夹、一行一步（新写 / 换已有 / 摘出 / 点按排序）、步间「连着 / 已拆开」分界——一次保存可拆成多条链；超过 8 步提示建议拆链 |
| 设置 | AI 接口（BYOK）+ 测试连接、JSON 导出/导入 |

**两类预案的分工**：`Rule.kind` 分 `ONE_OFF / REPEATING`，`status` 四态 `ACTIVE / ARCHIVED / DONE / MISSED`——一次性的结束是"有明确结果"（做了/没做），长期预案的归档是"这预案作废了"，两者不混用。一次性预案不分文件夹、不进链条，也不参与「全部战绩」「最常触发」「僵尸预案」的统计（未结清的一次性不该被判成僵尸），但它的打卡照常进热力图和流水。

**文件夹**：可无限嵌套，每个夹可选 emoji 和颜色。左滑卡片点「移夹」在清单里直接选目标夹（含根目录），编辑页的「所在文件夹」也能换。长按文件夹卡片可改名/改外观/连带删除。

**链**：真实体（`chains` 表：名字/文件夹/颜色/归档状态），成员靠 `Rule.chainId + stepIndex` 归属，严格线性、不分叉不成环，不再有 `nextRuleId` 指针。一条链只归一个文件夹，和散预案同级混排、共用一套排序；成员 ≥2 才算链，掉到 1 自动散成普通预案。链级操作在首页链头的 ⋯ 菜单（编辑整串/归档/设色/删除整串），改名和换夹在整串编辑页。删整串弹窗二选一：「只拆链」成员预案和打卡都留、「连预案一起删」永久删除。归档的链收进页底「已归档 N」折叠区，可撤销。折叠态存本机 DataStore，不进备份。设计决策见 [ADR-0001](docs/adr/0001-chain-as-first-class-entity.md)。

## 安装

到 [Releases](../../releases) 下载 `app-release.apk`，手机上安装（允许未知来源）。

**不要装 `app-debug.apk`**：debuggable 的包会被 ART 强制成解释执行，AOT 编译对它不生效，实测交互卡顿差 15 倍（详见「性能」）。v0.6 及之前发的就是 debug 包。

要求：Android 8.0+（minSdk 26）。数据全部存本地，AI 功能需要你自备一个 OpenAI 兼容接口（默认配置指向 DeepSeek）。

从 debug 包换到 release 包**必须卸载重装**（签名不同，覆盖装不上），卸载会清数据：先在旧版里「设置 → 导出 JSON 备份」，装新版后再「从 JSON 恢复」。

## 数据与隐私

- 所有预案和打卡记录存在设备本地（Room/SQLite），不经过任何服务器
- AI 生成候选时只把你输入的「困扰描述」发给 API，预案库不出门
- API Key 存 DataStore 私有目录，**不会**进入 JSON 导出文件
- 备份：设置页手动导出/导入 JSON（导入前会二次确认覆盖）

## 构建

```bash
# 需要 JDK 17 + Android SDK 35
echo "sdk.dir=/path/to/android-sdk" > local.properties
./gradlew assembleDebug     # 日常调试用（慢，见「性能」）
./gradlew assembleRelease   # 发布用：R8 压缩 + 资源收缩，产物 app/build/outputs/apk/release/app-release.apk
```

发版需要 `keystore.properties`（已 gitignore，放在仓库根目录），内容指向 `~/.android/ifthen-release.jks`。**这个密钥文件丢了就没法给已安装的设备平滑升级**，要单独备份到仓库之外。没有它时 release 会退回 debug 签名，只能本机自测。

技术栈：Kotlin · Jetpack Compose · Material 3 · Room · DataStore · OkHttp · kotlinx.serialization

## 性能

> **结论先行：卡顿的根因是「一直在发 debug 包」，不是 UI 代码。** debuggable 的应用 ART 会强制走解释器，AOT 编译和 Baseline Profile 对它都不生效。同一台手机同一个包，release 版把冷启动展开从 48ms 打到 3.2ms。

### 真机对照（Redmi Note 11T Pro，1080×2460 @145Hz，帧预算 6.9ms）

协议：交替安装两个包 → 冷启动 → 等 9s → `gfxinfo reset` → 单次动作 → 读 `framestats` 的 UI 线程时间（`SyncQueued − HandleInputStart`）。各 6 次。

| 冷启动首次动作 | debug 包 | release 包 |
|---|---|---|
| 点文件夹展开 | 48.4ms（49/48/48/49/48/48） | **3.2ms** |
| 点底部 tab 切页 | 20.9ms | **3.7ms** |

R8 压缩后的 release 包稳态：展开 5.9ms、点切页 2.8–3.3ms、列表滚动中位 0.5ms / p95 1.6ms，**480 帧里 0 帧超预算**。

### 怎么定位到的

`simpleperf record --app`（debuggable 包才能无 root 采样）抓冷启动首次展开：UI 线程上约 30% 的采样落在 `art::interpreter::ExecuteSwitchImplCpp`、`DoCall`、`NterpGetMethod`、`artQuickToInterpreterBridge`、`ResolveFieldWithAccessChecks`、`FindClassMethod` —— 全是解释器和类/方法解析，不是布局也不是绘制。

配套证据：**展开成本与卡片数量无关**。2 张 46ms、5 张 43ms、12 张 45ms —— 一次性开销（第一张卡触发类加载，后面复用热路径），不是每张卡片的测量成本。

### 之前记错的三条（已作废，别照着推）

1. ~~「5 张真实卡片 ≈ 20ms/张」~~ —— 上面那条数量无关实验直接推翻，成本是固定的。
2. ~~「强制全量 AOT 后尖峰不消失，所以不是 JIT 成本」~~ —— 测的是 debug 包，`cmd package compile` 对 debuggable 包不生效，这个实验等于没做。
3. ~~「v0.6 那批预组合/少图层的改动是原理上成立的优化」~~ —— 在 release 包上它们都没有可测收益；真正起作用的是换包。改动本身保留（少组合、少图层、主线程少算），但**不要把它们当成流畅度的来源**。

### 已实测排除（别再试）

`animateItemPlacement` 替换 · 去掉展开子项的 `animateItem()`（交替 A/B 反而更慢：21.6 vs 19.3ms）· 卡片 `weight(1f)` 换 `fillMaxWidth()` 少一次测量（噪声内）· 帧率状态移进 `graphicsLayer` · 关卡片阴影 · 去掉插入动画 · 去掉 `StreakChip` 的 `AnimatedContent` · alpha=1 时省图形层。

无障碍服务另说：K90 上手滑切页 12–18% 帧超预算，解绑后降到 2%——那是 Compose 每帧的语义遍历。release 包手滑 p95 只有 3.0ms，余量足够，暂未处理。

### 测量环境要求

- **性能结论必须在非 debuggable 的包上取**，debug 包量到的全是解释器成本。
- 模拟器（1200×2608@60Hz）上展开只要 10–22ms，真机 debug 包要 45–128ms，**差 20 倍**；但它的"是否超帧预算"仍能复现 debug 的问题，可用作廉价归因工具。
- 单次最差帧的对比不可信，必须**交替 A/B + 多次**（噪声地板 ±3 个百分点）。
- 手机测前务必 `svc power stayon true`：屏幕一睡，点击全打在黑屏上，测出来的是假数据。
